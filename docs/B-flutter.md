# B. Flutter 한 벌 — 웹(PC·모바일) + 안드로이드

코드 한 벌로 웹과 안드로이드 앱을 같이 만든다. 서버는 `00-shared-backend.md` 를 그대로 쓴다.

## 0. 읽는 법

- 규칙 내용은 `spec.md` 를 따른다. 표 안의 `§` 는 spec.md 의 장 번호, `S`·`F` 는 spec.md §2 화면 번호와 §3 흐름 번호다.
- `R1`~`R15`, `E1`, `T1`~`T10` 은 `00-shared-backend.md` 의 서버 함수·트리거 번호다.
- **(새로 정함)**: 이 문서에서 새로 정한 설계다. 절 제목에 붙어 있으면 그 절 전체가 새로 정한 것이다.
- **〔바뀔 수 있음〕**: spec 의 [추정]·[미확인] 규칙이나 spec 이 "앱에서 확인 필요"로 표시한 값을 구현하는 곳이다. 8장에 모았다.
- spec 은 "원본 우선 방침"(spec.md §0)을 따른다. 화면 문구도 spec 에 적힌 원본 문구(영어 그대로인 것 포함)를 쓴다.

## 4. 플랫폼별 처리 (새로 정함)

### 4.1 알림 (spec.md §5.10, §7.12)

| | 안드로이드 | 웹 |
|---|---|---|
| 시각 계산 | core/rules/reminder_time (같은 코드) | 같음 |
| 울리는 방법 | 기기 로컬 알림 예약. 정확한 알람 권한을 요청하고, 거부되면 부정확 알람으로 내려간 뒤 안내 | 브라우저 알림. **탭이 열려 있는 동안만** 울린다. 탭이 뒤에 있으면 브라우저가 타이머를 늦추므로 1분마다 "지난 알림"을 확인해 울린다 |
| 예약 범위 | 앞으로 14일 안의 알림 중 가까운 것부터 최대 400건 (기기 예약 수 상한 대비) | 다음 24시간 |

| 권한 | 알림 권한, 정확한 알람 권한 | 브라우저 알림 권한 (사용자 동작 뒤에 묻기) |

웹에서 탭을 닫으면 알림이 울리지 않는다. 서버 푸시를 쓰지 않기로 해서(spec.md §7.12) 생기는 한계다. 화면에 "웹은 탭이 열려 있을 때만 알림" 안내를 둔다.

### 4.2 집중 타이머 (spec.md §5.14)

- **상태는 시각 기록으로만 둔다.** 시작 시각과 구간 목록(집중·일시정지의 시작·끝)만 저장하고, 남은 시간·집중 합은 늘 "지금 − 기록"으로 계산한다. 그래서 앱이 죽었다 살아나도, 웹 탭이 잠들었다 깨어나도 같은 값이 나온다. 이 기록이 spec 의 상태 스냅샷(§5.14.5)이다.
- 상태 전이와 저장 판정(§5.14.2, §5.14.6, §5.14.7)은 core/rules/focus 하나가 맡는다. 플랫폼 코드는 "사건을 넣고 결과를 그린다"만 한다.
- 종료 유형은 원본 것을 모두 둔다(뽀모도로 0·1·2·5·6·8, 스톱워치 0·1·2·4·5). 버튼과의 연결은 00 문서 10장 〔바뀔 수 있음〕. 미리 완료(유형 6)는 남은 시간이 5분 미만일 때 원본 문구로 확인을 묻는다 (§5.14.2).
- 5분 관문을 넘은 뒤 버린 집중은 `discarded: true` 로 R11 에 보내 무효 기록으로 남긴다 (§5.14.6, §7.10).

| | 안드로이드 | 웹 |
|---|---|---|
| 돌리는 곳 | 포그라운드 서비스 + 진행 알림(일시정지·재개·끝내기 버튼) | 탭 안 |
| 끝나는 시각 | 정확한 알람 (§5.14.3 "바뀐 뒤") | 탭 안 타이머 + 브라우저 알림 |
| 종료 팝업 S14-1 | 전체 화면 알림. 권한이 없으면 눈에 띄는 알림으로 대신함 | 화면 안 대화상자 + 브라우저 알림 |
| CPU·화면 깨우기 | 부분 깨우기 잠금, 화면 켜 두기 설정 | 브라우저 화면 깨우기 기능 (지원할 때만) |
| 배경음·알림음 | 서비스가 재생 | 탭이 열려 있을 때만 |
| 스냅샷 | 로컬 DB | 로컬 DB(drift 웹) |
| 복원 | 앱 시작 때 스냅샷으로 되살리고 §5.14.3 의 복원 규칙 적용 | 탭 열 때 같은 방식 |
| 기록 저장 | R11, 오프라인이면 쓰기 대기열 | 같음 |

### 4.3 오프라인

- 두 플랫폼 모두 **로컬 DB 우선**이다. 화면은 drift 를 읽고, 쓰기는 drift 에 먼저 하고 대기열에 넣는다. 동기화 방식은 00 문서 8장의 "안드로이드" 열을 웹에도 그대로 쓴다.
- RPC 가 필요한 처리(R1 등)도 로컬에 같은 결과를 먼저 반영하고, 대기열에는 RPC 호출과 클라이언트가 만든 ID·계산값을 넣는다. 서버 RPC 가 멱등이라 다시 보내도 안전하다 (00 문서 5.1).
- 웹 브라우저가 로컬 저장소를 막으면(사생활 보호 창 등) 메모리 DB 로 돌리고 "오프라인 사용 불가" 표시를 띄운다. 이때는 온라인 우선처럼 동작한다.
- 삭제 되돌리기 대기(§5.11.7)는 00 문서 8.5 대로 한다. 대기 중에는 로컬 DB 에도 쓰지 않는다. 안내가 (되돌리기 없이) 닫히면 그 묶음을, 목록 화면을 떠나면 가장 최근 묶음을 확정해 로컬 반영 + R4 를 쓰기 대기열에 넣는다. 안드로이드는 목록 화면이 안 보이게 될 때, 웹은 탭이 숨겨질 때(`visibilitychange` → hidden)를 "화면을 떠남"으로 본다.
- 웹에서 탭을 닫을 때도 브라우저가 먼저 "숨겨짐"을 알리므로 가장 최근 묶음만 로컬 DB 에 확정해 둔다. 쓰기 대기열은 다음에 탭을 열 때 보낸다. 나머지 묶음과 안드로이드 강제 종료 때의 대기분은 원본처럼 확정하지 않는다 〔바뀔 수 있음: §5.11.7 앱 실행 확인 필요〕.
- 안내 없는 삭제는 대기열을 거치지 않고 바로 R6. 반복 "이 회차만"·"이 회차와 이후"는 바뀐 반복 정보를 바로 로컬 + 대기열에 쓰고, 되돌리면 원래 값을 다시 쓴다.

- 안드로이드 태블릿·폴더블·가로 화면도 같은 기준을 쓴다 (§5.7 의 전체화면 처리와 맞춤).
- PC 입력: 스와이프 동작(F8, F9)은 행에 마우스를 올리면 나오는 버튼으로도 할 수 있다. 오른쪽 클릭 = 길게 누르기 메뉴. 단축키(새 할 일, 완료, 검색)를 둔다.
- 캘린더 뷰는 폭과 관계없이 spec 의 뷰 규칙(§5.13)을 그대로 쓴다. 좁은 폭에서도 7일 뷰를 고를 수 있다.

## 5. 공통 규칙 구현과 테스트 (새로 정함)

### 5.1 어디에

- `core/rules/` 한 곳. Flutter·Supabase·drift 를 가져오지 않는 순수 Dart 다. 화면·서비스·데이터 층이 모두 이 모듈을 부른다.
- 지금 시각과 시간대는 `core/clock/` 으로 주입한다. 규칙 코드가 직접 시계를 읽지 않는다.
- 반복 계산은 전부 여기서 한다 (spec.md §7.6, 00 문서 1장): 회차 펼치기(기준일 −30일 ~ +60일), 다음 발생일, 반복 완료 결과, 날짜를 바꿀 때 규칙 다시 만들기, 범위별 결과, 지난 회차 정리, 체크리스트 자동 완료 판정과 진행률. 서버 함수는 그 결과를 저장만 한다.
- 아젠다 거름, 특수 목록 조건(§5.11.2 의 오늘·내일·최근 7일), 한도 비교도 여기서 한다.

### 5.2 어떻게 테스트할지

| 대상 | 방법 |
|---|---|
| spec 예시표 (§5.2, §5.6, §5.9.3, §5.9.6, §5.9.7, §5.10.3, §5.10.5, §5.12, §5.13.5, §5.14.3, §5.14.6, §5.14.7) | `shared-testdata/` JSON 을 읽는 표 기반 테스트. 케이스 이름에 장 번호를 넣는다 |
| 웹과 안드로이드에서 같은 결과인지 | 같은 테스트를 **Dart VM 과 Chrome 둘 다**에서 돌린다. 웹 컴파일에서는 정수가 JS 숫자라서 큰 정수·날짜 계산이 달라질 수 있다 |
| 시간대 | 모든 날짜 테스트를 `Asia/Seoul` 과 서머타임이 있는 시간대 하나로 두 번 돌린다 |
| 표준 RRULE 의미(§5.9.6 B) | 보정을 거치지 않는 규칙은 표준 RRULE 패키지 결과와 비교하는 차등 테스트 |
| 범위 판정(§5.9.8) | 표의 모든 줄을 케이스로 |
| 공휴일·근무일 규칙(§5.9.1, §5.9.3) | 공휴일 표 기준 케이스(공식 근무일, `TT_SKIP`, `TT_WORKDAY`, `ERULE`) |
| 삭제 대기열(00 문서 8.5) | 확정 시점 시나리오(안내 닫힘, 화면 떠남, 강제 종료·탭 닫기) |
| 집중 상태 전이 | 사건 순서 → 기대 상태·저장 여부 시나리오 테스트 (시계를 앞으로 돌리며) |
| 데이터 층 | drift 메모리 DB + 가짜 원격으로 대기열·충돌 처리 테스트 |
| 서버 | `supabase/tests/` SQL 테스트 (00 문서) |
| 흐름 | integration_test 로 F1~F13 중 핵심(F1, F2, F3, F6, F8, F9, F11, F12)을 안드로이드 에뮬레이터와 Chrome 에서 |

### 9.2 안드로이드 전용 기능의 구현

Flutter 로 만들 수 없는 홈 화면·시스템 기능은 `android/` 안의 **Kotlin 네이티브 코드**로 만든다. 원칙은 두 가지다.

1. **규칙은 Dart 에만 둔다.** Kotlin 은 그리기와 시스템 연결만 한다. 할 일을 바꾸는 동작(체크, 빠른 추가, 완료 처리)은 Kotlin 이 **Dart 백그라운드 콜백**(앱 화면 없이 Flutter 엔진을 하나 띄워 Dart 함수를 부르는 방식)으로 넘긴다. 반복 완료(spec.md §5.9.7)를 두 언어로 만들지 않기 위해서다.
2. **Kotlin 이 읽는 데이터는 Dart 가 써 둔 스냅샷이다.** Dart 는 저장할 때마다 위젯·타일·제공자가 쓸 표시용 데이터(JSON)를 기기 저장소에 쓰고 갱신을 알린다. Kotlin 이 drift 표를 직접 해석하지 않으므로 스키마가 바뀌어도 Kotlin 은 그대로다. 데이터 제공자(15.13)만 예외로 읽기 전용 질의를 한다.

| 기능 | ext | 구현 |
|---|---|---|
| 위젯 27종 | 15.10, 15.11 | 위젯 수신기·원격 화면(RemoteViews, 목록은 컬렉션 위젯)은 Kotlin. 표시 데이터는 Dart 스냅샷(위젯 ID 별). 덮개(모듈 꺼짐·업그레이드)와 상태 코드도 스냅샷에 넣어 Kotlin 은 그리기만 한다. 체크·빠른 추가·목록 넘기기는 Dart 백그라운드 콜백 → 처리 → 스냅샷 다시 쓰기 → 갱신. 위젯 설정 화면은 Flutter 화면(설정 결과를 위젯 설정 표에 씀). 주기 갱신 30분은 WorkManager. 위젯 잠금(15.8)이면 스냅샷에 할 일을 넣지 않는다 |
| 빠른 설정 타일 2개 | 15.12 | 타일 서비스는 Kotlin. 누르면 앱 링크로 Flutter 경로(빠른 추가 / 음성 추가)를 연다. 잠겨 있으면 잠금 해제 뒤 실행 |
| 퀵볼 | 15.12 | 다른 앱 위에 그리는 Kotlin 오버레이 서비스(포그라운드). Pro 판정은 Dart 가 스냅샷에 넣는다. 누르면 빠른 추가 경로 |
| 떠 있는 창 | 14.8 | 집중 포그라운드 서비스가 오버레이 창을 띄운다. 남은 시간은 집중 상태 기록(4.2)으로 Kotlin 이 계산해 1초마다 그린다(규칙 계산 아님, 시각 빼기만). 버튼은 Dart 로 사건을 넘긴다. 창 위치는 기기 설정 |
| 엄격 모드 | 14.6 | 집중 서비스 안에서 Kotlin 이 1초마다 사용 정보로 맨 앞 앱을 본다. 허용 목록·홈 앱이면 통과, 아니면 덮개 창. 허용 목록은 Dart 가 메서드 채널로 넘긴다. 사용 정보 접근 권한 안내 화면은 Flutter |
| 집중 서비스 | 14.1~14.9 | 4.2 의 플러그인 대신 **Kotlin 포그라운드 서비스**로 바꾼다(떠 있는 창·엄격 모드·라이브 진행 알림을 한 서비스가 맡아야 해서). 상태 전이 규칙은 계속 Dart(core/rules/focus)이고, 서비스는 끝나는 시각 알람·진행 알림·소리만. 알람이 울리면 Dart 백그라운드 콜백으로 다음 상태를 정한다 |
| 뒤집어서 시작 | 14.5 | 센서 플러그인으로 Dart 가 판정(집중 화면이 열려 있을 때). 판정식은 core/rules/focus |
| 패턴 잠금·지문 | 15.8 | 잠금 화면은 Flutter(패턴 그리기). 지문은 생체 인증 플러그인. 패턴 해시는 보안 저장소 플러그인. 판정(경과 > 설정 초 × 1000)은 앱 생명주기에서 Dart. 팝업·위젯 잠금 플래그는 스냅샷에 반영 |
| 앱 아이콘 바꾸기 | 15.3 | 매니페스트에 런처 별칭 26개. 메서드 채널로 Kotlin 이 하나만 켜고 나머지를 끈다. 첫 변경 재시작 안내는 Flutter |
| 다른 앱에 데이터 제공 | 15.13 | Kotlin 콘텐츠 제공자. 읽기 경로는 drift 의 SQLite 파일을 **읽기 전용**으로 열어 질의한다(열 이름 대응표는 `android/` 안 상수 파일 하나). `markTaskDone` 은 Dart 백그라운드 콜백으로 넘긴다(반복 완료 규칙). "접근 권한" 설정이 꺼져 있으면 빈 결과 |
| 다른 앱과 주고받기 | 15.14 | 공유 받기·텍스트 선택·나에게 보내기·알람 설정은 매니페스트 인텐트 필터 + Kotlin 진입 화면. 화면이 필요한 것은 앱 링크로 Flutter 편집 화면에, 화면 없는 생성(나에게 보내기·알람)은 Dart 백그라운드 콜백으로 |
| 기기 캘린더 | 15.15 | 기기 캘린더 플러그인으로 읽기·쓰기. 7일 안 알림 할 일 넣기는 주기 작업. 대응표는 drift 기기 전용 테이블 |
| 알림 확장 | 13.9~13.14 | 로컬 알림 플러그인의 채널별 소리, 지속(상주) 알림, 전체 화면 알림. 끈질긴 알림의 1분 울림·2분 뒤 다시는 Kotlin 이 알람으로 다시 예약하고 5분에 멈춘다. 알림 팝업(다른 앱 위)은 전체 화면 알림, 권한이 없으면 눈에 띄는 알림 |
| 생일 가져오기 | 14.13 | 연락처 플러그인 |
| 문서 스캔 | 13.18 | 기기 문서 스캐너 플러그인 |
| 앱 배지 | 14.10 | 배지 플러그인(런처가 지원할 때만) |
| vivo 원격 호출, 웨어러블 | 17.3, 17.4 | 만들지 않는다 (연결 안 됨) |

### 9.5 위험 추가

| 위험 | 영향 | 대응 |
|---|---|---|
| Dart 백그라운드 콜백이 늦거나 안 뜸(엔진 띄우는 시간, 배터리 제한) | 위젯 체크가 늦게 반영 | E0 에서 확인. 늦으면 위젯에는 "처리 중"을 먼저 그린다 |
| Kotlin 코드가 커짐(위젯 27종·서비스·오버레이·제공자) | "한 벌" 이득이 줄어듦 | 규칙은 Dart 에만(9.2 원칙 1), Kotlin 은 스냅샷 그리기만 |
| 집중 서비스를 플러그인에서 Kotlin 으로 옮김 | 8단계 결과 재작업 | 4.2 의 "상태는 시각 기록으로만" 덕분에 서비스만 바꾼다 |
| 협업 권한이 화면 곳곳에 퍼짐 | 버튼이 보이는데 서버가 거절 | `core/rules/permissions` 하나로 모든 화면이 판정, 서버 RLS 와 같은 표를 테스트 케이스로 |
| 그림·소리 자산을 새로 만들어야 함 (spec-ext X8) | 일정 밖 작업 | 이름·묶음·Pro 구분만 먼저 넣고 자리 표시 그림으로 시작 |
