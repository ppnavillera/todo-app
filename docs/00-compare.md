# 00. B 와 C 비교 — 확장 범위 (원본 기능 전부)

- B = `B-flutter.md` (Flutter 한 벌로 웹 + 안드로이드. 안드로이드 전용 기능은 Kotlin 네이티브 코드)
- C = `C-web-nextjs.md` + `C-android-kotlin.md` (Next.js 웹 + Kotlin 안드로이드)
- 범위는 spec.md §1 이 넓힌 **원본 기능 전부**다: spec.md(핵심 기능) + `spec-ext.md` 12~17장(확장 기능). 이전 비교(spec.md 범위만)는 `spec-backup/spec-platform-before-12/00-compare.md` 에 있다.
- 두 안 모두 서버는 `00-shared-backend.md`(1~10장 + 확장 11장)를 그대로 쓴다. 그래서 아래 비교는 **클라이언트의 차이**다.
- 이 문서의 추산·비교·추천은 모두 새로 정한 판단이다 **(새로 정함)**. 주 수는 각 플랫폼 문서 6장(spec.md 범위)과 9장(확장)의 단계별 추산을 더한 값이고, 실측이 아니다.

## 3. 확장 범위에서 달라진 점

1. **규칙이 더 늘었다.** 필터 엔진(조건 16종, 날짜 토큰 14개), 다른 달력 9종, 망각 곡선, 스누즈, 습관 연속 3종, 디데이 표시, 시간표 교시, 하루 계획 한도, 협업 권한이 모두 클라이언트 계산이다. 두 벌을 맞추는 비용(C)은 이전보다 커졌다.
2. **안드로이드 전용 기능이 들어왔다.** 위젯 27종, 타일, 퀵볼, 떠 있는 창, 엄격 모드, 잠금, 아이콘 바꾸기, 데이터 제공자, 기기 캘린더. 이 부분은 C 가 유리하다. B 도 이 부분은 Kotlin 으로 만들고(약 6.5주), Dart 와 잇는 비용이 C 보다 약 1주 더 든다.
3. **협업이 들어왔다.** 서버 일(11장)은 두 안이 같다. 클라이언트의 권한 판정·실시간 처리는 B 는 한 번, C 는 두 번 만든다.
4. 결과: B 와 C 의 차이는 1인 기준 약 13주(이전)에서 약 31~32주로 벌어졌다. B 안의 Kotlin 비중은 전체의 약 11% 다.

## 4. 추천: B 유지 — 단, 안드로이드 전용 기능은 Kotlin 네이티브로 (새로 정함)

이유:

1. **규칙이 화면보다 어렵다는 이전 판단이 확장으로 더 강해졌다.** 서버가 결과를 다시 계산하지 않으므로(spec.md §7.6) 두 언어 구현이 어긋나면 그대로 다른 데이터가 저장된다. 확장으로 이런 규칙 모듈이 2배 넘게 늘었고, 공유 목록에서는 웹 사용자와 안드로이드 사용자가 **같은 할 일을 서로 다른 규칙으로** 고치게 된다. B 는 이 위험이 구조적으로 작다.
2. **일이 약 35% 적다.** 1인 약 58주 대 약 90주, 2인 약 32~35주 대 약 49~52주다.
3. **C 의 강점(안드로이드 시스템 기능)은 B 에서도 같은 코드로 얻는다.** 위젯·타일·오버레이·엄격 모드·제공자는 어느 안이든 Kotlin 이다. B 는 여기에 "Dart 백그라운드 콜백" 연결 비용(약 1주)과 콜백 반응 지연이 더 붙을 뿐이다. 규칙을 Dart 에만 두는 원칙(B 문서 9.2)으로 Kotlin 은 그리기만 하므로, 규칙이 두 벌이 되지 않는다.
4. 웹 오프라인(로컬 DB 우선)이 협업에서 더 중요해졌다. 공유 목록을 쓰다 연결이 끊겨도 B 웹은 쓰기를 이어 간다.
5. 이전 추천과 같은 쪽이지만, **B 안에 Kotlin 네이티브 묶음이 정식으로 들어간다**는 점과 **집중 서비스를 Kotlin 으로 옮긴다**는 점이 달라졌다.

## 5. 단계 나누기 제안 (새로 정함)

전체가 1인 약 58주라 한 번에 끝내기 어렵다. 의존 관계와 원본 확인 상태(spec-ext 18장)를 보고 아래 순서로 내놓는 것을 권한다.

| 단계 | 범위 | B 1인 누적(주) | 고른 이유 |
|---|---|---|---|
| 1 | spec.md 범위 | 18~18.5 | 다른 모든 기능의 바탕 |
| 2 | 12장 목록 보기(필터 엔진·칸반·매트릭스·검색·하루 계획 등) + 15장 공통 설정 | +11 | 필터 엔진을 여러 기능이 같이 쓴다. 서버가 거의 필요 없다 |
| 3 | 13장 작성·알림 확장 + 14장 집중·습관·디데이·시간표 | +12 | 개인 기능이라 협업 없이 완결된다 |
| 4 | 15장 안드로이드 전용 (위젯 등) | +7 | 2·3단계의 화면·데이터가 있어야 위젯이 그릴 것이 있다 |
| 5 | 16장 협업 + 서버 확장의 협업 부분 | +8 | 권한이 모든 화면에 걸쳐 마지막에 넣는 편이 재작업이 적다 |
| 6 | 17장 "연결 안 됨", 자산 마무리 | +2 | 가장 싸다. 어느 단계 끝에 붙여도 된다 |

- 16주 과제라면 1단계 + 2단계 일부(필터 엔진·매트릭스·검색)까지가 현실적이다(2인 B 기준).
